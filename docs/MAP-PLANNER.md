# 港巴通：地图与路线规划系统扩展

日期：2026-10-20。状态：源码、必要测试、四端编译、真实接口及正式 H5 浏览器验收已完成。官方 IDE、真机、平台上传及商店发行未验收。

用户目标：自行深入检查、优化和扩展现有内容，完善完整地图相关模块以及路线规划与核查模块。保留 Accessible Calm Minimal、Logo 10、四入口导航、繁简英、真实 KMB/LWB 与独立 TDAS，以及无乘客账号的前端本机资料规则。不调整旧 demo、prototype、Vercel 或旧 mobile。使用 Windows 原生工具，检查结束关闭本次浏览器。

## 本次源码查明的缺口

1. 街道地图已接入，但仅作为路线、道路和附近的局部组件；不能在独立地图浏览任意区域、查询当前视野、在地图选点再规划。
2. 附近没有定位时读取整个目录第一页，地图只含这一页而非当前区域，用户无法理解展示范围。
3. 规划只查询直达或一次同物理站码转乘，并在已有三条直达时不再搜索转乘；每侧只取前 30 条线路，存在无提示截断。
4. 通过 findIndex 选择物理站首次出现，循环线路会忽略后续合法上下车组合；转乘 ID 也没有精确上下车站序。
5. 没有地图起终点、附近站转乘、两次转乘、步行限制、完整行程地图和逐段出发核查。旧结果中的站序、车费和可用性没有集中复核流程。
6. 路线规划只展示站数/车费，不能解释搜索覆盖和候选限制；不应补造总耗时、换乘成功率或车辆位置来填补。

## 搜索与数据契约

公交仍限 KMB/LWB。完整地图表示完成本站查车/选点/区域发现与行程可视化流程，不表示全港所有交通营办商、实时车辆或商业导航。规划使用有向官方站序图，最多三段巴士。附近站步行连接由公开坐标计算直线距离，以 75 米/分钟估算；不具备真实人行路、楼梯、过海、障碍或无障碍验证，默认同站转乘，用户可明确开启附近站候选。

搜索采用分轮、多标签、有界候选算法，处理所有现行路线，避免之前前 30 条和三条直达即停止的问题。候选/标签有服务器上限，返回 limited、候选统计和非穷尽声明；不承诺全网最优、最低票价或最快。没有可靠的逐段乘车耗时与后续候车预测，不制造总到达时刻。

新增 GET `/v1/map/stops` 视野查询，扩展 POST `/v1/journeys` 的地图点、转乘/步行限制和搜索统计；新增 POST `/v1/journeys/check`，以路线 ID、上下车 ID/站序重新核对目录和当前到站。精确位置仅存在内存和当次请求，不进入本机缓存、个人档案或日志。跨页面详情草稿保存在内存；刷新后清楚提示重新查询。

地图实现参考 [Taro Map](https://docs.taro.zone/docs/components/maps/map)、已安装 Taro 4.3 的官方类型与 [MapLibre Map API](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/)。延续已确认的方案五，UI/UX Pro Max 用于触点、无障碍和移动交互核查；搜索返回的通用营销版式不替换已锁定产品风格。


## 业务流程与页面交付

正式客户端由 17 页扩展到 **19 页**，新增独立 Map 和完整 Journey details。地图入口位于首页，也可从附近、道路、路线和到站进入；主导航仍为首页、路线、收藏、设置。Map 可以无定位浏览当前区域，手动搜索、缩放、点站、切换列表或选择中心点；同一官方站卡复用真实 ETA 和本机收藏。

Planner 接受官方站或本次内存点，保留跨页面草稿，支持交换/清除、接驳范围、总步行限制、最多两次转乘与候选筛选/排序/比较。默认最多一次同站转乘；不会擅自启用邻站步行。打开完整行程后按当前目录重新核查每程精确上下车站序，再独立取得 ETA、官方运营参考及车费，绘制选中区间几何，展开本程全部途经站。结构 valid 不代表正在营运或一定赶得上换乘。

参数和上下限、响应字段、状态机、原生坐标、时效、几何匹配、缓存和清除事务详见[完整 API 与业务契约](MAP-PLANNER-API.md)。本次修复了无定位附近误列全局第一页、前 30 条路线截断、已有三条直达就放弃转乘、循环线仅取首次物理站，以及地图列表图标引用缺失。
